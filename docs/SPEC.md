# BUILD A PRODUCTION-READY BUSINESS WEBSITE WITH CMS, SEO, WHATSAPP & CUSTOMER INQUIRY CHATBOT

Build a complete, production-ready, modern business website with a secure Content Management System (CMS), admin dashboard, database, advanced technical SEO, local SEO, WhatsApp integration, customer inquiry chatbot, image management, analytics readiness, and strong performance.

The website must not be a static template where content is hard-coded. Normal website content must be manageable by an administrator through the admin dashboard without editing source code.

---

## 1. CORE OBJECTIVE

Create two connected systems:

### A. Public Website

A beautiful, professional, fast, responsive website that customers can access from phones, tablets and computers.

### B. Secure Admin Dashboard / CMS

A protected administration system where authorized administrators can manage the public website, content, images, products/services, SEO, WhatsApp, chatbot, contact information, social media and other settings.

Any changes made through the admin dashboard must automatically appear on the public website and, where applicable, become available to the customer inquiry chatbot.

## 9. SEO-FRIENDLY URLS

Use clean URLs such as:

`/services`

`/services/web-development`

`/products/laptop-hp-840`

`/about`

`/contact`

Avoid URLs containing unnecessary parameters, database IDs or meaningless strings.

Allow administrators to change slugs safely.

When an existing published URL is changed, automatically create a 301 redirect from the old URL to the new URL where appropriate.

## 16. WHATSAPP INTEGRATION

Add a floating WhatsApp button.

The button must work on:

* Mobile
* Tablet
* Desktop

The WhatsApp number must be configurable from the admin dashboard.

Do not hard-code the number into frontend source code.

Use the international phone number format required by WhatsApp.

Generate a WhatsApp click-to-chat URL dynamically.

Allow the administrator to configure the default message.

Example:

> Hello, I would like to know more about your products/services.

Also allow different WhatsApp messages for different contexts.

For example:

### Product

> Hello, I am interested in [PRODUCT NAME]. Please provide more information.

### Service

> Hello, I would like to enquire about [SERVICE NAME].

### General Contact

> Hello, I would like to contact your business.

The system should URL-encode the message correctly.

## 19. CHATBOT KNOWLEDGE SOURCE

The chatbot must use the **actual information stored in the website CMS/database** as its primary source of business information.

For example:

If the administrator adds:

**Product:** HP EliteBook 840 G8
**Price:** KES 65,000
**Availability:** In Stock

The chatbot should be able to answer a customer asking:

> "How much is the HP EliteBook 840 G8?"

using the current published database information.

If the administrator changes the price to KES 62,000, the chatbot must use the updated information.

The chatbot must not rely on outdated hard-coded information.

## 20. CHATBOT ACCURACY & ANTI-HALLUCINATION

The chatbot must prioritize accuracy.

It must NOT invent:

* Products
* Services
* Prices
* Discounts
* Stock availability
* Business locations
* Opening hours
* Payment methods
* Delivery information
* Policies
* Guarantees
* Contact information

If the required information is not available, the chatbot should respond honestly, for example:

> "I don't have that information at the moment. Would you like to speak with our team on WhatsApp?"

Never make up an answer simply to keep the conversation going.

## MOST IMPORTANT RULE

Do not build only the visual frontend first and leave the CMS, chatbot or SEO as an afterthought.

Design the database, CMS, public website, SEO architecture, WhatsApp system and customer inquiry chatbot as **one integrated application**.

The administrator should be able to launch and maintain the website without needing a developer for ordinary changes.

If a feature can reasonably be controlled through the CMS, make it configurable through the admin dashboard instead of hard-coding it.

The chatbot must use current information from the CMS/database and must never invent business information.

Build the system as if it will be used by a real paying business client and maintained for several years.
